# Easypoint Design Principles

These principles are decision tools for product, design, engineering, sales, and operations. Use them when two reasonable options conflict.

## Prefer Trust Over Drama

If a claim cannot be proven in the product, remove it, qualify it, or replace it with observable product behavior.

- Use real coverage, real partners, and real metrics only when the source is available.
- Prefer "available points by zone" over national scale claims until coverage data supports the claim.
- Never simulate operational artifacts such as QR codes, confirmations, or partner logos.

## Make The Next Action Obvious

When a screen has multiple audiences, the primary task wins over brand flourish.

- Consumers should see tracking and point discovery first.
- Local partners should see requirements and the application path.
- Ecommerce partners should see integration paths and how results will be measured.

## Accessibility Is Operational Quality

If a flow must work for someone using keyboard, assistive tech, slower devices, or reduced motion, it becomes better for everyone.

- Dialogs need labels, close affordances, and Escape handling.
- Forms need labels, autocomplete hints, error states, and honest success states.
- Motion and decoration must not block comprehension or task completion.

## Evidence Beats Assumptions

Use data to decide when to scale, not to decorate marketing copy.

- Conversion, cost, coverage, and reliability numbers need a named source or dashboard.
- Launch experiments should define what is measured before the claim appears on the site.
- If the data is not ready, describe the measurable workflow instead of the outcome.
